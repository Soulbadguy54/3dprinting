## Independent Google Drive backups

This does **not** verify a restore from Google Drive.
The server had Ubuntu rclone 1.60.1; its built-in self-update refused to accept the new checksum signature, so it was not bypassed. Instead, rclone v1.75.2 was independently installed to `/usr/local/bin/rclone` only after verification of the vendor's PGP-signed `SHA256SUMS` against the published signing fingerprint `FBF737ECE9F8AB18604BD2AC93935E02FF3B54FA` and SHA-256 of the downloaded archive. Ubuntu's original package remains installed.
For headless Google OAuth, use official instructions: https://rclone.org/remote_setup/ and https://rclone.org/drive/. Rclone's shared Google OAuth client is being retired during 2026; prefer a personal desktop OAuth client from Google Cloud (configured with Drive API). Connect with SSH port forwarding `ssh -L 53682:localhost:53682 root@111.88.215.215`, run `rclone config` on VPS, create Drive remote named `rateapp-drive`, use browser auto config over the forwarded loopback port; create a `crypt` remote named `rateapp-crypt` pointing at `rateapp-drive:RateAppEncrypted` with filename encryption and generated strong passphrases; keep the passphrases and an encrypted offline copy of `rclone.conf` securely **outside** the VPS, so recovery survives server loss. Test actual upload and download and restore before enabling timer.

The VPS executes `deploy/scripts/backup-to-gdrive.sh` using PostgreSQL `pg_dump -Fc` and `pg_restore --list` validation. Uploads use **rclone crypt** remote `rateapp-crypt` to encrypt files before they arrive in the owner's Google Drive. Configure rclone Drive OAuth and crypt key locally through protected setup, never by chat or repo commit. Confirm a real download **and restore** test before enabling `deploy/systemd/rateapp-backup.timer`; initial suggested schedule is daily 03:40 UTC.
